## Honest Feedback
- **Tunnel Lifecycle Management:** I initially forgot to kill the old Quick Tunnel process when spinning up the Named Tunnel. While it didn't cause a conflict, leaving orphaned tunnels running is bad practice and wastes resources. I need to be more disciplined with task cleanup.
- **Action Update UX:** I underestimated how confusing it is for a user to update a Custom GPT action. I assumed changing the URL was enough, but I had to explicitly tell them to delete the old action and start a New Chat to clear the cache. I should provide these comprehensive steps upfront.
- **Security Communication:** I didn't preemptively warn the user about the "Always Allow" button disappearing for unauthenticated God Mode endpoints. Setting that expectation earlier would have prevented their frustration.

## Lessons Learned
- **Cloudflare Token Portability:** A Cloudflare tunnel token generated via the dashboard can be executed on any architecture or OS, making it extremely easy to shift the networking burden from the user's host OS to the agent's WSL environment.
- **ChatGPT Action Caching:** Custom GPTs aggressively cache action schemas and routing. Updating an action requires deleting the old one, re-importing, AND starting a fresh chat session to guarantee the new routing is applied.
- **OpenAI Security UI:** OpenAI dynamically hides the "Always Allow" permission button for Custom Actions that lack explicit authentication (like API Keys) or execute highly privileged operations, forcing manual user confirmation for every execution to prevent silent malicious activity.
