## Honest Feedback & Lessons Learned
- **Mathematical Rigor in Test Fixtures**: Synthetic test data for identity numbers must strictly satisfy checksum algorithms (Modulo 11 for Thai Citizen ID) to avoid false test failures.
- **Binary Signature Defenses**: Relying on client-reported MIME types is insufficient; reading magic bytes from decoded memory buffers provides true defense-in-depth against polyglot and extension spoofing.
- **Single-Stream Resilience**: Downstream resumption must be controlled by a single authoritative state machine (the server) to avoid race conditions and partial state leakage across client retries.

## Addendum: Resolving Host Test Failures (Harness Header Delegation & Dynamic Config)
- **Root Cause 1 (Header Collision in `startFakeBridge`)**: `startFakeBridge` wrote 200 SSE headers unconditionally before invoking custom `onChat`. When HTTP error tests called `res.writeHead(500)`, headers were already sent, causing `streamBridgeCompletion` to hang for 30s. Resolved by delegating header responsibility to custom handlers and emitting 200 SSE headers only in the fallback `else`.
- **Root Cause 2 (Module-Load Config Snapshot & Process.env Race)**: `CONFIG` in `lib/config.mjs` was snapshot at module evaluation time before `startStudioServer` modified `process.env`. Concurrency tests never pointed to the fake bridge and concurrency locks never engaged. Resolved by introducing `getConfig(overrides)` and wrapping `CONFIG` in a dynamic `Proxy`, passing overrides directly to `createServer()` without mutating `process.env`.
- **Root Cause 3 (Deterministic Synchronization)**: Replaced arbitrary 30ms sleep in concurrency tests with an awaited `conversationStarted` Promise, guaranteeing the live lock is held before firing concurrent requests.
